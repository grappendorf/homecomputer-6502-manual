The computer has to do many things at once: fetch characters from the ACIA, scan the keyboard, measure time, later play tones. This chapter shows how that works with interrupts.

Why interrupts?

You could look again and again in the main program whether something has happened. That is called polling and is a good solution for small tasks. For example one can build a state machine that checks events in a loop, executes actions and changes its state.

It gets difficult with delays. A delay loop blocks the main program, it cannot do anything else meanwhile. Above all it cannot fetch a byte from the ACIA right away so that its receive register becomes free.

Better is a mechanism that interrupts the main program and calls a special subroutine when something happens. That is an interrupt.

How the processor interrupts

The 6502 has two interrupt inputs:

  • /IRQ (interrupt request) is an input that triggers on low, as long as it stays low. It can be blocked: the flag I in the status register blocks it. SEI sets the flag, CLI clears it.
  • /NMI (non-maskable interrupt) triggers on the falling edge and cannot be blocked.

On an interrupt the processor finishes the current instruction, saves the program counter and the status register on the stack, sets the flag I and jumps through a vector: through $FFFE and $FFFF for /IRQ, through $FFFA and $FFFB for /NMI. This takes seven clocks. The instruction RTI restores status register and program counter, and the main program continues where it was interrupted.

Important: the interrupt routine has to save all registers it changes, and it has to clear the cause of the interrupt. Otherwise the processor jumps right back in.

The circuit

Most chips for the 6502 have an output /IRQ that reports that something happened inside the chip, for example a timer overflow or a received byte. These outputs are open collector (open drain with MOS chips): they only pull the line down. You can connect all /IRQ lines together and run them to the /IRQ input of the processor. The resistor R9 (3.3 kΩ) from chapter 3 keeps the line high otherwise. Such a circuit is called “wired OR”.

The /IRQ of the ACIA (pin 26), of the first and second VIA (pin 21 each) and the /IRQ input of the 6502 (pin 4) are connected. The input /NMI gets a button to GND. Its pull-up is R8 from chapter 3. The button triggers an interrupt that can later be used for a warm start, for example.

The program

The example blinks the LED with timer 1 of the first VIA as in chapter 8, but without a delay loop. The timer runs continuously: it counts down with every clock of φ2, triggers an interrupt at zero and reloads the start value. With 10,000 that gives an interrupt every 100 ms. Because of two extra clocks for reloading it is exactly 10.002 ms.

In the interrupt the program counts up to 100 and then toggles the LED, that is once per second. An NMI sets the limit to 10, and the LED then changes every tenth of a second.

RegisterValueMeaning
ACR ($7F2B)%01000000timer 1 runs continuously, PB7 stays free
IER ($7F2E)%11000000bit 7 set: switch the given bits on, bit 6: timer 1 interrupt
T1C-L, T1C-H ($7F24, $7F25)10000start value, low byte first, then high byte

The interrupt of timer 1 is cleared by reading T1C-L. The handler does that first. The instructions SEI and CLI block and release /IRQ.

        .setcpu "6502"

VIA1_ORA  = $7f21
VIA1_DDRA = $7f23
VIA1_T1CL = $7f24
VIA1_T1CH = $7f25
VIA1_ACR  = $7f2b
VIA1_IER  = $7f2e

LED            = %10000000
TIMER_INTERVAL = 10000          ; one interrupt every 100 ms (at 1 MHz)

        .zeropage
ticks:      .res 1              ; interrupts counted
max_ticks:  .res 1              ; number of interrupts until the LED changes

        .segment "VECTORS"
        .word   nmi
        .word   reset
        .word   irq

        .code
reset:  jmp main
nmi:    jmp nmi_handler
irq:    jmp irq_handler

main:   sei                     ; block interrupts until everything is set up
        cld
        ldx #$ff
        txs
        lda VIA1_DDRA           ; PA7 (the LED) as output, LED off
        ora #LED
        sta VIA1_DDRA
        lda VIA1_ORA
        and #<;~LED
        sta VIA1_ORA
        lda #0
        sta ticks
        lda #100                ; 100 times 100 ms: the LED changes every second
        sta max_ticks
        lda #%01000000          ; timer 1 runs continuously, PB7 stays free
        sta VIA1_ACR
        lda #%11000000          ; enable the timer 1 interrupt
        sta VIA1_IER
        lda #<;TIMER_INTERVAL    ; load the counter: low byte first, then high byte
        sta VIA1_T1CL
        lda #>;TIMER_INTERVAL
        sta VIA1_T1CH
        cli                     ; enable interrupts
loop:   jmp loop                ; the main program has nothing to do

; NMI: from now on the LED changes ten times faster
nmi_handler:
        pha
        lda #10                 ; 10 times 100 ms: the LED changes every tenth of a second
        sta max_ticks
        pla
        rti

; IRQ: every 100 ms
irq_handler:
        pha
        lda VIA1_T1CL           ; reading T1C-L clears the interrupt request
        inc ticks
        lda ticks
        cmp max_ticks
        bcc @done
        lda #0
        sta ticks
        lda VIA1_ORA
        eor #LED                ; toggle the LED
        sta VIA1_ORA
@done:  pla
        rti

Note

The example uses only one interrupt source. As soon as several chips may trigger /IRQ, the handler has to check all sources (the flag register IFR of the VIAs, bit 7 of the ACIA status) and clear each one separately. Otherwise the line stays low and the processor never gets out of the interrupt.
