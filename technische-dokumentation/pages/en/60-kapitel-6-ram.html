With just the three registers A, X and Y you do not get far. Now the computer gets working memory. For this the address decoding needs more logic: it has to tell the RAM apart from the EEPROM and from the ACIA.

The memory map

We use a static RAM of 32 KB in the lower half of the address space. The top 256 bytes of this half are not meant for RAM, though, but for the input and output chips. Their registers live at $7F00 to $7FFF. This is the memory map:

AddressesContents
$0000 to $00FFRAM, zero page
$0100 to $01FFRAM, stack
$0200 to $7EFFRAM
$7F00 to $7FFFInput/output (IO)
$8000 to $FFFFROM (EEPROM)

The processor expects zero page and stack in the first two pages ($0000 to $01FF). That is why RAM belongs there.

Three chip select signals control the chips. A slash in front of the name means “active low”, the symbol ¬ is negation and ∧ is the logical AND:

  • /CS_ROM = ¬A15
  • /CS_IO = ¬(/CS_ROM ∧ A14 ∧ A13 ∧ A12 ∧ A11 ∧ A10 ∧ A9 ∧ A8)
  • /CS_RAM = ¬(RAM ∧ φ2) with RAM = ¬(/CS_ROM ∧ /CS_IO)

So the RAM is selected when neither ROM nor IO is selected, and only during the second half of the clock (φ2 high). For a write access the data bus is only valid then. If the RAM were enabled earlier, it could be written wrongly for a moment when the address changes.

The circuit

The signal /CS_IO is generated by an 8-input NAND gate 74LS30. Its eight inputs are A8 to A14 and /CS_ROM. The output is low when all eight are high, which is exactly the case at $7F00 to $7FFF.

/CS_RAM comes from a 74LS00 (four NAND gates) and one more inverter of the 74LS04. Gate A combines /CS_ROM and /CS_IO into /RAM. The inverter IC1E turns it into RAM, and gate B combines RAM with φ2.

The RAM 61256 has the same pinout as the EEPROM. /CE and /OE come from /CS_RAM, /WE from the R/W line of the processor. The ACIA gets /CS_IO at /CS1 instead of A15. That puts it into the IO area at $7F00 to $7F03, repeating every four addresses.

Assembly

First build the IO decoding, change the program addresses and check that “Hello World!” still runs. Only then comes the RAM.

A test program

The program extends “Hello World!”: it first copies the text into RAM and then sends it from there. If it arrives unchanged, RAM and address decoding work. The label string_data lives in RAM, in the DATA section.

        .setcpu "6502"

ACIA_DATA    = $7f00
ACIA_STATUS  = $7f01
ACIA_COMMAND = $7f02
ACIA_CONTROL = $7f03

        .segment "VECTORS"
        .word   nmi
        .word   reset
        .word   irq

        .data
string_data:
        .res    16              ; 16 bytes in RAM

        .code
reset:  jmp main
nmi:    rti
irq:    rti

main:
init_acia:
        lda #%00001011          ; no parity, no echo, no interrupts
        sta ACIA_COMMAND
        lda #%00011111          ; 1 stop bit, 8 data bits, 19200 baud
        sta ACIA_CONTROL

        ldx #$ff                ; copy the text from ROM to RAM
copy_string:
        inx
        lda text,x
        sta string_data,x
        bne copy_string

write:  ldx #0
next_char:
wait_txd_empty:
        lda ACIA_STATUS
        and #$10
        beq wait_txd_empty
        lda string_data,x       ; characters now come from RAM
        beq read
        sta ACIA_DATA
        inx
        jmp next_char

read:
wait_rxd_full:
        lda ACIA_STATUS
        and #$08
        beq wait_rxd_full
        lda ACIA_DATA
        jmp write

text:   .byte "Hello World!", $0d, $0a, $00

For this the linker needs an extended configuration. It describes the RAM as the area for the DATA section and the first 256 bytes as ZEROPAGE. With file="" we tell the linker that these areas do not belong into the output file, otherwise the RAM ends up in the ROM file:

MEMORY
{
  ZP:  start=$0000, size=$0100, type=rw, define=yes, file="";
  RAM: start=$0200, size=$7d00, type=rw, define=yes, file="";
  ROM: start=$8000, size=$8000, type=ro, define=yes, fill=yes, file=%O;
}
SEGMENTS
{
  ZEROPAGE: load=ZP,  type=zp, define=yes;
  DATA:     load=RAM, type=rw, define=yes;
  CODE:     load=ROM, type=ro;
  VECTORS:  load=ROM, type=ro, offset=$7ffa;
}
$ ca65 -o ramtest.o ramtest.s
$ ld65 -C ram.cfg -o ramtest.bin ramtest.o
$ minipro -p AT28C256 -w ramtest.bin

If “Hello World!” shows up in the terminal, everything ran via the RAM.

Measuring

The picture shows the chip select signals for a read access to $7F01 (status of the ACIA) and a write access to $0200 (RAM). The curves are calculated from the equations. In every clock exactly one chip is selected: ROM when fetching the instructions, IO when reading the status, RAM when writing. /CS_RAM only goes low in the second half of the clock.

Note

Program does not run? First use the old program from chapter 5 to check whether the ACIA answers at $7F00. If it does, the fault is in the RAM part: at /CS_RAM (pin 6 of IC6), the wiring of IC1E or the address and data lines to the 61256.
