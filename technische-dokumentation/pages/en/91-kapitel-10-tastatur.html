After the display the computer needs an input. A notebook keyboard is ideal for this: it is flat, has more than 80 keys and consists of nothing but a switch matrix. A second VIA comes along for it.

The keyboard matrix

A keyboard with 80 keys would need 80 lines if every key got its own connection. Instead the keys are arranged in a grid. Each key connects a row line to a column line. With a matrix of 14 rows and 8 columns, 22 lines are enough for 112 keys.

Reading works like this: the rows are outputs, the columns inputs. The computer puts exactly one row low and reads all columns. The inputs have a pull-up resistor and therefore read 1 as long as no key pulls them down. If a key is pressed in the selected row, the matching column reads a 0. Row by row this builds up a picture of all keys.

From row and column a scancode is made: row × 8 + column. It runs from 0 to 111. The value $FF means “no key”.

Two things need attention. Mechanical contacts bounce: when pressed they switch back and forth for a few milliseconds. The program therefore scans twice, 10 ms apart, and only believes what is the same both times. And without diodes at the keys, several keys pressed at the same time can create “ghost keys”. Our program therefore reports only one key at a time.

Your own keyboard

Another keyboard has another matrix. Measure it: expose the connection pads of the foil and hold one probe of a continuity tester to a pad. With the other probe touch the remaining pads while you press all keys one after the other. The tester beeps when a key connects the two pads. Note the pair of pads for every key. The pads fall into two groups, the rows and the columns.

The circuit

A second VIA (IC11) gets the output Y2 of the decoder as chip select. It thus lives at $7F40 to $7F5F: port B at $7F40, port A at $7F41, the direction registers at $7F42 and $7F43.

  • Columns: port A of the second VIA, PA0 to PA7, as inputs. The 6522 has its own pull-up resistors at port A, so external ones are not needed.
  • Rows 0 to 7: port B of the second VIA, PB0 to PB7, as outputs.
  • Rows 8 to 13: PB0 to PB5 of the first VIA. That is why the LED moved from PB0 to PA7 in chapter 9. PB6 and PB7 stay free.

The keyboard is connected to the pin header JP3 by 22 wires. In the drawings the rows are called R0 to R13 and the columns C0 to C7:

Assembly

First the decoder gets its second output:

  1. Switch the power off. Bring out Y2 (pin 13 of IC10, hole 8j) as /CS_VIA2.

Then the second VIA:

  1. Run +5 V and GND to a new breadboard and connect the upper rails to the lower ones there.
  2. Insert IC11 across the channel, notch left, pin 1 in hole 4d (wide IC, rows d and h).
  3. Power as for the first VIA: pin 20 (hole 23a) to +5 V, pin 1 (4a) to GND, CS1 (pin 24, hole 20j) to +5 V. C15 between the upper rails. /IRQ (pin 21) stays open.
  4. Connect the control wires to the connections of the same name. The table shows the pins.

The program

The program reports every newly pressed key with its scancode over the serial interface. keys_scan scans the 14 rows one after the other. keys_update repeats the scan after 10 ms and keeps the code only if both results agree.

Important: rows 8 to 13 are at port B of the first VIA, whose PB6 and PB7 may be used otherwise. The program therefore changes only the lower six bits, with a mask. The main program:

        .setcpu "6502"

ACIA_DATA    = $7f00
ACIA_STATUS  = $7f01
ACIA_COMMAND = $7f02
ACIA_CONTROL = $7f03
VIA1_ORB     = $7f20
VIA1_DDRB    = $7f22
VIA2_ORB     = $7f40
VIA2_IRA     = $7f41
VIA2_DDRB    = $7f42
VIA2_DDRA    = $7f43

        .zeropage
ptr:    .res 2
tmp:    .res 1
code:   .res 1                  ; code of the pressed key ($FF = none)
last:   .res 1                  ; last code reported

        .segment "VECTORS"
        .word   nmi
        .word   reset
        .word   irq

        .code
reset:  jmp main
nmi:    rti
irq:    rti

main:   cld
        ldx #$ff
        txs
        jsr acia_init
        jsr keys_init
        lda #$ff
        sta last
loop:   jsr keys_update
        lda code
        cmp last                ; report changes only
        beq loop
        sta last
        cmp #$ff
        beq loop                ; releasing is not reported
        lda #<;msg_key
        ldx #>;msg_key
        jsr puts
        lda code
        jsr puthex
        jsr newline
        jmp loop

Scanning the keyboard:

; set up the ports: rows output, columns input
keys_init:
        lda #$ff
        sta VIA2_DDRB           ; VIA2 port B: rows 0 to 7 as outputs
        lda #$00
        sta VIA2_DDRA           ; VIA2 port A: columns 0 to 7 as inputs
        lda VIA1_DDRB
        ora #$3f                ; VIA1 PB0 to PB5: rows 8 to 13 as outputs
        sta VIA1_DDRB
        jmp rows_idle

; all rows high
rows_idle:
        lda #$ff
        sta VIA2_ORB
        lda VIA1_ORB
        ora #$3f
        sta VIA1_ORB
        rts

; X = row (0 to 13): only this row low
select_row:
        jsr rows_idle
        cpx #8
        bcs @via1
        lda row_mask,x
        sta VIA2_ORB
        rts
@via1:  lda row_mask - 8,x
        and VIA1_ORB
        sta VIA1_ORB
        rts

row_mask: .byte $fe, $fd, $fb, $f7, $ef, $df, $bf, $7f

; scan the keyboard: A = scancode or $FF
keys_scan:
        ldx #0
@row:   jsr select_row
        lda VIA2_IRA
        eor #$ff                ; pressed = bit set
        bne @found
        inx
        cpx #14
        bne @row
        jsr rows_idle
        lda #$ff
        rts
@found: ldy #0
@bit:   lsr
        bcs @done
        iny
        bne @bit
@done:  sty tmp                 ; Y = column
        txa
        asl
        asl
        asl
        ora tmp                 ; row * 8 + column
        pha
        jsr rows_idle
        pla
        rts

; scan with debouncing: code in code
keys_update:
        jsr keys_scan
        cmp #$ff
        beq @none
        sta code
        ldx #10                 ; wait 10 ms and scan again
        jsr delay_ms
        jsr keys_scan
        cmp code
        beq @done
@none:  lda #$ff
        sta code
@done:  rts

delay_ms:
@ms:    ldy #199
@us:    dey
        bne @us
        dex
        bne @ms
        rts

The routines for output through the ACIA (putc, puts, puthex and newline) you know from chapter 7. The complete program is in programme/en/tastatur.s.
