So far the processor has only read NOPs. Now it gets a read-only memory that you program yourself, and it runs its first program of its own. Along the way you replace the home-made clock with a ready-made module.

The read-only memory

If you want the feeling of the eighties, use EPROMs of the 27C series and a UV eraser. But erasing takes more than a quarter of an hour, and during development you have to reprogram very often. That quickly becomes tedious.

So we use a modern parallel CMOS EEPROM, the AT28C256 from Atmel. It holds 32 KB (32k × 8 bits) and can be erased and written electrically. You need a programmer for it. A universal device like the MiniPro TL866 works well. Under Linux the command line tool minipro controls it.

Since the chip keeps travelling between the programmer and the circuit, a ZIF socket (zero insertion force) in the circuit is worth it. It has a lever and needs no force when inserting.

The circuit

The AT28C256 is connected to the address bus (A0 to A14) and the data bus (D0 to D7). It also has three control inputs: /CE (chip enable), /OE (output enable) and /WE (write enable).

/CE and /OE are tied to GND, so the chip is always active and outputs its data. /WE is tied to +5 V, so the processor cannot overwrite the memory. There is no address decoding yet. That is why the EEPROM appears in the whole address space, once at $0000 to $7FFF and once at $8000 to $FFFF. The reset vector is there as well.

The clock now comes from a crystal oscillator module QG1 in a metal case. It delivers 1 MHz at TTL level and has four connections: pin 14 (+5 V), pin 7 (GND), pin 8 (output) and pin 1 (a control input on some types, tied to GND here). This makes R1, R2, C1 and Q1 from chapter 1 unnecessary, and gates A to C of the 74LS04 are free.

Assembly

First you swap the clock. Breadboard 1 then looks like this, the circuit is otherwise unchanged:

  1. Switch the power off. Remove R1, R2, C1, the crystal Q1 and the wire from pin 4 to pin 5 of IC1. Also pull off the wire that carried the clock from pin 6 to the processor.
  2. Insert QG1 to the right of the button, pin 1 in hole 28e.
  3. Pin 14 (hole 28j) goes to +5 V. Pin 1 (28a) and pin 7 (34a) go to GND.
  4. Run the clock from pin 8 (hole 34j) to pin 37 of the 6502 (hole 7j on breadboard 2), and /RESET from hole 11j to pin 40 (hole 4j).

Now the EEPROM on a new breadboard. The short named wires show where a connection goes. Wires with the same name belong together.

  1. Run +5 V and GND from breadboard 2 to breadboard 3 and connect the upper rails to the lower ones there.
  2. Insert IC4 across the channel, notch left, pin 1 in hole 5d. Like the 6502 it is 600 mil wide and sits in rows d and h. Better use a ZIF socket.
  3. Power IC4: pin 28 (hole 5j) to +5 V and pin 14 (18a) to GND. Place C7 between the upper rails.
  4. /OE (pin 22, hole 11j) and /CE (pin 20, hole 13j) go to GND. /WE (pin 27, hole 6j) goes to +5 V.
  5. Connect the 15 address and 8 data lines to the processor, each to the one with the same name. The table shows the pins. Use green wires for the addresses and blue for the data, it makes checking easier.

Caution

Insert the EEPROM into the socket only with the power off, and check the orientation first. A chip inserted the wrong way round is quickly destroyed.

Software

For the programs we use the cc65 tool suite: the assembler ca65 and the linker ld65. The linker needs a configuration file that describes the memory. The first version, first.cfg:

MEMORY
{
  ROM: start=$8000, size=$8000, type=ro, define=yes, fill=yes, file=%O;
}
SEGMENTS
{
  CODE:    load=ROM, type=ro;
  VECTORS: load=ROM, type=ro, offset=$7ffa;
}

There is one memory area ROM from $8000 to $FFFF. That is the file we will write into the EEPROM later. The VECTORS section ends up at offset $7FFA, that is at $FFFA to $FFFF. That is where the processor expects its three vectors.

The first program, first.s, does almost nothing. After the reset the processor jumps to the label loop, loads $12 into the accumulator and jumps back:

        .setcpu "6502"

        .segment "VECTORS"
        .word   loop            ; NMI
        .word   loop            ; Reset
        .word   loop            ; IRQ

        .code
loop:   lda #$12
        jmp loop

Assemble it and write it into the EEPROM:

$ ca65 -o first.o first.s
$ ld65 -C first.cfg -o first.bin first.o
$ minipro -p AT28C256 -w first.bin

The result is a file of 32 KB. The three vectors are at the end, all pointing to $8000:

If the chip is write-protected, the minipro option -u removes the protection.

Measuring

With a logic analyzer you can see what happens on the buses after the reset. The drawing shows the clock, the R/W line and the two buses as numbers. Each column is one bus cycle, that is one clock.

The processor first reads the reset vector, then it runs the program:
