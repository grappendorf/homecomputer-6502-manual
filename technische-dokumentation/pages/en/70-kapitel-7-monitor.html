From now on the computer becomes a tool for itself. A small program in ROM takes commands from the PC and lets you look at memory, change it and start programs. This chapter needs no new hardware.

What a monitor does

A monitor is a supervisor program: it sits in ROM, waits for commands and executes them. Our first monitor knows only three. From here one can grow it into a full tool with an assembler, disassembler, register display, breakpoints, single stepping and loading and saving of programs.

CommandEffect
m <address>show 16 bytes from the address as hex numbers and as characters
w <address> <byte>write the byte to the address
j <address>jump to the address. An RTS returns to the monitor.

You enter addresses and bytes in hexadecimal, in upper or lower case and without a dollar sign.

A session

After switching on, the monitor reports in the terminal. At power-on the RAM contains random values, so yours will look different:

The display has the address at the front, then 16 bytes in two groups of eight and on the right the characters between vertical bars. Bytes that cannot be printed show up as a dot. To w the monitor answers with the value it reads back from memory afterwards. If the address cannot be written, for example in ROM, you would still see the old value there.

With w and j you can type in a program byte by byte and start it. This one prints an asterisk:

  • A9 2A is LDA #'*',
  • 8D 00 7F is STA $7F00 and sends the character to the ACIA,
  • 60 is RTS and returns to the monitor.

Structure of the program

The program is split into small subroutines. Do not look for optimization of space or speed in it. What mattered was that the code stays readable and easy to change.

  • Main loop: it prints the prompt >, reads a line and branches on the first letter to one of the three commands.
  • Commands: cmd_memory, cmd_write and cmd_jump. Unknown commands and missing numbers lead to the message “Unknown command”.
  • Reading input: gets reads characters up to the end of the line (Return), allows backspace and ignores control characters. parse_hex turns a hex number of the line into a 16-bit value.
  • Output: puts prints a text, puthex a byte as two hex digits.
  • ACIA: putc and getc send and receive one character each and wait for the status bit.

The jump with j needs a small trick: the 6502 has no JSR through a pointer. So cmd_jump calls the label call with JSR, and there stands JMP (val). The RTS of the called program then returns behind the JSR.

The variables live in RAM. The zero page holds the pointers, the input line starts at $0200, and the stack grows downwards from $01FF as always.

The program

First the configuration. New is the BSS section for variables without an initial value. It lives in RAM and does not go into the ROM file:

MEMORY
{
  ZP:  start=$0000, size=$0100, type=rw, define=yes, file="";
  RAM: start=$0200, size=$7d00, type=rw, define=yes, file="";
  ROM: start=$8000, size=$8000, type=ro, define=yes, fill=yes, file=%O;
}
SEGMENTS
{
  ZEROPAGE: load=ZP,  type=zp,  define=yes;
  BSS:      load=RAM, type=bss, define=yes;
  CODE:     load=ROM, type=ro;
  VECTORS:  load=ROM, type=ro, offset=$7ffa;
}

Then the main loop:

        .setcpu "6502"

ACIA_DATA    = $7f00
ACIA_STATUS  = $7f01
ACIA_COMMAND = $7f02
ACIA_CONTROL = $7f03

BUFLEN = 80

        .zeropage
ptr:    .res 2                  ; pointer for strings and memory access
val:    .res 2                  ; value from parse_hex
tmp:    .res 1                  ; scratch variable

        .bss
buffer: .res BUFLEN + 1         ; input line

        .segment "VECTORS"
        .word   nmi
        .word   reset
        .word   irq

        .code
reset:  jmp main
nmi:    rti
irq:    rti

main:   cld
        ldx #$ff                ; initialize the stack
        txs
        jsr acia_init
        lda #<;msg_welcome
        ldx #>;msg_welcome
        jsr puts

loop:   lda #<;prompt
        ldx #>;prompt
        jsr puts
        jsr gets                ; read a line
        lda buffer
        beq loop                ; empty line: do nothing
        cmp #'m'
        bne @check_w
        jsr cmd_memory
        jmp loop
@check_w:
        cmp #'w'
        bne @check_j
        jsr cmd_write
        jmp loop
@check_j:
        cmp #'j'
        bne @unknown
        jsr cmd_jump
        jmp loop
@unknown:
        jsr error
        jmp loop

The three commands:

; print an error message
error:  lda #<;msg_unknown
        ldx #>;msg_unknown
        jmp puts

; m <address>: show 16 bytes
cmd_memory:
        ldy #1
        jsr parse_hex
        bcs @error
        lda val
        sta ptr
        lda val+1
        sta ptr+1
        lda ptr+1               ; print the address
        jsr puthex
        lda ptr
        jsr puthex
        jsr space
        jsr space
        ldy #0
@hex:   lda (ptr),y
        jsr puthex
        jsr space
        cpy #7
        bne @next
        jsr space               ; gap between the two halves
@next:  iny
        cpy #16
        bne @hex
        jsr space
        jsr space
        lda #'|'
        jsr putc
        ldy #0
@ascii: lda (ptr),y
        cmp #' '
        bcc @dot                ; printable characters only, else a dot
        cmp #$7f
        bcc @put
@dot:   lda #'.'
@put:   jsr putc
        iny
        cpy #16
        bne @ascii
        lda #'|'
        jsr putc
        jmp newline
@error: jmp error

; w <address> <byte>: write a byte
cmd_write:
        ldy #1
        jsr parse_hex
        bcs @error
        lda val
        sta ptr
        lda val+1
        sta ptr+1
        jsr parse_hex           ; second value: the byte
        bcs @error
        lda val
        ldy #0
        sta (ptr),y             ; store the byte
        lda ptr+1
        jsr puthex
        lda ptr
        jsr puthex
        lda #':'
        jsr putc
        lda (ptr),y             ; read back for checking
        jsr puthex
        jmp newline
@error: jmp error

; j <address>: call a program, RTS returns
cmd_jump:
        ldy #1
        jsr parse_hex
        bcs @error
        jsr call
        rts
@error: jmp error
call:   jmp (val)               ; JSR to here, JMP to the target: its RTS returns to cmd_jump

Input: reading and printing hex numbers.

; Reads a hex number from position Y of the input into val. Carry set: no number.
parse_hex:
        lda #0
        sta val
        sta val+1
@skip:  lda buffer,y
        cmp #' '
        bne @first
        iny
        bne @skip
@first: jsr hexdigit
        bcs @none
@digit: sta tmp
        asl val                 ; val = val * 16
        rol val+1
        asl val
        rol val+1
        asl val
        rol val+1
        asl val
        rol val+1
        lda val
        ora tmp
        sta val
        iny
        lda buffer,y
        jsr hexdigit
        bcc @digit
        clc
        rts
@none:  sec
        rts

; A = character -> A = value 0..15, carry set: not a hex digit
hexdigit:
        cmp #'0'
        bcc @no
        cmp #'9' + 1
        bcc @decimal
        ora #$20                ; convert to lower case
        cmp #'a'
        bcc @no
        cmp #'f' + 1
        bcs @no
        sec
        sbc #'a' - 10
        clc
        rts
@decimal:
        sec
        sbc #'0'
        clc
        rts
@no:    sec
        rts

; print A as two hex digits
puthex: pha
        lsr
        lsr
        lsr
        lsr
        jsr @nibble
        pla
        and #$0f
@nibble:
        cmp #10
        bcc @digit
        adc #'A' - 10 - 1       ; carry is set: +1
        jmp putc
@digit: ora #'0'
        jmp putc

space:  lda #' '
        jmp putc

newline:
        lda #$0d
        jsr putc
        lda #$0a
        jmp putc

Reading a line and printing text. Finally the character input and output through the ACIA and the texts:

; print text, address in A (low) and X (high)
puts:   sta ptr
        stx ptr+1
        ldy #0
@loop:  lda (ptr),y
        beq @done
        jsr putc
        iny
        bne @loop
@done:  rts

; read a line into buffer, backspace allowed
gets:   ldx #0
@loop:  jsr getc
        cmp #$0d
        beq @done
        cmp #$08
        beq @back
        cmp #$7f
        beq @back
        cmp #' '
        bcc @loop               ; ignore control characters
        cpx #BUFLEN
        bcs @loop
        sta buffer,x
        inx
        jsr putc                ; echo the character
        jmp @loop
@back:  cpx #0
        beq @loop
        dex
        lda #$08
        jsr putc
        lda #' '
        jsr putc
        lda #$08
        jsr putc
        jmp @loop
@done:  lda #0
        sta buffer,x
        jmp newline
; ACIA: output and input of one character
acia_init:
        lda #%00001011
        sta ACIA_COMMAND
        lda #%00011111
        sta ACIA_CONTROL
        rts

putc:   pha
@wait:  lda ACIA_STATUS
        and #$10
        beq @wait
        pla
        sta ACIA_DATA
        rts

getc:   lda ACIA_STATUS
        and #$08
        beq getc
        lda ACIA_DATA
        rts

prompt:      .byte ">; ", $00
msg_welcome: .byte $0d, $0a, "Welcome to the 6502 monitor program!", $0d, $0a, $00
msg_unknown: .byte "Unknown command", $0d, $0a, $00

Assembling and starting

$ ca65 -o monitor.o monitor.s
$ ld65 -C monitor.cfg -o monitor.bin monitor.o
$ minipro -p AT28C256 -w monitor.bin

Connect the converter, start the terminal program with picocom -b 19200 /dev/ttyUSB0 and switch the computer on. The monitor reports with its prompt.

Note

The program sends Return and Line Feed at the end of a line. From your terminal it expects only Return. If a Line Feed arrives as well, it is ignored. Jump with j only to addresses where a program really is. Otherwise the computer crashes and you have to reset it.
