BASIC ist bequem, aber für manche Dinge zu langsam. Dann spricht man den Prozessor direkt an. Ein Maschinenprogramm ist eine Folge von Bytes im Speicher. Der 6502 führt sie der Reihe nach aus. Dieses Kapitel zeigt den Prozessor, ein paar Befehle und die Wege, so ein Programm zu laden und aus BASIC zu starten.

Der Prozessor 6502

Der 6502 rechnet mit einem Byte, einer Zahl von 0 bis 255. Er kennt 65536 Speicherplätze, von 0 bis 65535. Im Maschinencode schreibt man Adressen hexadezimal, mit einem Dollarzeichen davor: $0000 bis $FFFF. BASIC will dieselben Adressen dezimal.

RegisterBreiteAufgabe
A8 Bitder Akku. Hier landet das Rechenergebnis
X und Y8 Bitzählen und Adressen bilden
PC16 BitAdresse des nächsten Befehls
S8 Bitzeigt auf den Stapel
P8 BitMerker, etwa ob das letzte Ergebnis null war

Zwei Bereiche haben feste Aufgaben. Der Stapel liegt bei $0100 bis $01FF. Dorthin legt der Prozessor die Rücksprungadresse, wenn er ein Unterprogramm aufruft. Die Zero Page, $0000 bis $00FF, erreicht er mit kürzeren Befehlen. Die benutzt BASIC selbst.

BereichAdresseInhalt
Programm$0440–$7EFFBASIC und Ihre Maschinenprogramme
Ein- und Ausgabe$7F00–$7FFFAnzeige, Tastatur, serielle Schnittstelle, SID
Festspeicher$8000–$FFFFBASIC, Kernal und Monitor

Die genaue Belegung steht in Anhang C.

Ein paar Befehle

Ein Befehl beginnt mit einem Byte, dem Opcode. Dahinter folgen oft ein oder zwei Bytes: ein Wert oder eine Adresse. Das Zeichen # bedeutet: nimm diese Zahl selbst, nicht den Inhalt einer Speicherstelle.

BefehlBeispielWirkung
LDALDA #65lädt 65 in den Akku, den Buchstaben A
STASTA $7E00schreibt den Akku an die Adresse
LDXLDX #0lädt das Register X
JSRJSR $FF80ruft das Unterprogramm an der Adresse auf
RTSRTSkehrt aus dem Unterprogramm zurück

JMP $7E00 springt ebenfalls, merkt sich aber keine Rückkehradresse. Eine Adresse steht im Speicher mit dem niedrigen Byte zuerst. Aus $FF80 werden die Bytes 128 und 255.

Maschinenprogramme laden

Ein fertiges Maschinenprogramm liegt meist in einer Datei mit der Endung .prg, wie beim Commodore 64. Die ersten zwei Bytes sind die Ladeadresse, das niedrige zuerst. Sie muss $0441 sein, also die Bytes 65 und 4. Dahinter steht eine BASIC-Zeile, die nur SYS und die Startadresse enthält, und dahinter der Maschinencode.

LOAD "name" legt das Abbild ab und setzt das Ende der Variablen dahinter, damit RUN den Code nicht überschreibt. LIST zeigt die SYS-Zeile, RUN führt sie aus. Passt die Adresse nicht oder ist die Datei zu groß, bleibt der Speicher leer und es steht BAD LOAD. SAVE schreibt nur die BASIC-Zeilen, den Maschinencode nicht.

Das Spiel raid ist so eine Datei. Ist das Laufwerk aus Kapitel 6 verbunden, starten LOAD "raid" und RUN es. Hoch und runter weichen den Wänden aus, Q kehrt nach BASIC zurück.

Dieselben Bytes können Sie auch von Hand ablegen: im Monitor aus Kapitel 6, dort startet G, oder aus BASIC mit POKE, wie am Ende dieses Kapitels.

SYS, PEEK und POKE

POKE Adresse, Wert schreibt ein Byte. PEEK(Adresse) liest eines. SYS Adresse springt dorthin. Endet das Maschinenprogramm mit RTS, läuft BASIC danach weiter.

POKE 32256,96
PRINT PEEK(32256)
SYS 32256

32256 ist $7E00, weit oben im Arbeitsspeicher. 96 ist der Befehl RTS. PRINT zeigt zur Kontrolle 96, SYS kehrt sofort zurück. Adresse und Wert müssen passen: die Adresse von 0 bis 65535, der Wert von 0 bis 255. Sonst kommt ?ILLEGAL QUANTITY ERROR.

Achtung

POKE schreibt überall hin, auch mitten in Ihr BASIC-Programm. Das beginnt bei 1089 ($0441). Zero Page und Stapel gehören dem System. Der Festspeicher ab 32768 ($8000) lässt sich nicht ändern.

Die Kernal-Sprungtabelle

Ab $FF80 liegen feste Einsprünge für Anzeige, Tastatur und Ton. Ein Maschinenprogramm ruft sie mit JSR auf. Die Adressen bleiben, auch wenn sich die Firmware dahinter ändert. A, X und Y werden dabei verändert. Nur beim Lesen der Taste bleiben X und Y erhalten.

AdresseAufrufWirkung
$FF80JSRAnzeige löschen
$FF83JSRCursor setzen. A ist die Zeile 0 bis 3, X die Spalte 0 bis 39
$FF86JSRdas Zeichen in A ausgeben
$FF89JSRUnterstrich: A = 0 aus, sonst an
$FF8CJSRTaste nach A, oder 0 wenn keine gedrückt ist
$FF8FJSRA Millisekunden warten
$FF92JSRSID stumm schalten
$FF95JSREffekt, A = 1 bis 9 wie bei EFFECT

Die Pfeiltasten kommen als 17 links, 18 rechts, 19 hoch und 20 runter.

Ein Maschinenprogramm aus DATA

Statt einer .prg-Datei kann BASIC die Bytes selbst ablegen. READ holt sie aus DATA, POKE schreibt sie, SYS startet. Dieses Programm löscht die Anzeige und schreibt links oben ein A:

BytesBefehlWirkung
32, 128, 255JSR $FF80Anzeige löschen
169, 65LDA #65den Buchstaben A in den Akku
32, 134, 255JSR $FF86das Zeichen ausgeben
96RTSzurück nach BASIC
 
10 AD=32256
20 FOR I=0 TO 8
30 READ B
40 POKE AD+I,B
50 NEXT I
60 SYS AD
70 DATA 32,128,255,169,65,32,134,255,96

Die neun Bytes in Zeile 70 stehen in derselben Reihenfolge wie in der Tabelle. $FF80 wird zu 128, 255 und $FF86 zu 134, 255. Zeile 60 springt an 32256. Danach wartet BASIC wieder auf eine Eingabe.

Hinweis

32256 ($7E00) liegt weit oben, weg vom BASIC-Programm. Textvariablen legt BASIC vom oberen Speicherende her ab. Viele oder lange Texte können diese Bytes überschreiben.
