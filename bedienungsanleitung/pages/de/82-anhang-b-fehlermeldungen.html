BFehlermeldungen

Eine Fehlermeldung beginnt mit einem Fragezeichen und endet mit ERROR. Läuft ein Programm, folgt IN und die Zeile:

?SYNTAX ERROR IN 10

Im Direktmodus fehlt die Zeile. Das Programm bleibt stehen. Die Variablen behalten ihren Wert, Sie können sie mit PRINT ansehen. Korrigieren Sie die Zeile und starten Sie mit RUN neu.

BREAK IN 10 ist keine Fehlermeldung. Pause, Strg+C oder STOP haben angehalten. CONT läuft weiter.

Im Programm

NEXT WITHOUT FOR

?NEXT WITHOUT FOR ERROR

Ein NEXT hat kein passendes FOR. Der Name hinter NEXT muss derselbe sein wie hinter FOR, oder Sie lassen ihn weg.

10 NEXT Ikein FOR I davor

Schreiben Sie die Schleife vollständig, zum Beispiel 10 FOR I=1 TO 5 und 20 NEXT I.

SYNTAX

?SYNTAX ERROR

Der Computer versteht die Zeile nicht. Oft ist ein Befehl falsch geschrieben, ein Zeichen fehlt, oder in einem Namen steckt ein BASIC-Wort.

10 PRONT "HALLO"PRINT falsch geschrieben

Die Zeile muss heißen 10 PRINT "HALLO". Steht der Fehler in einer DATA-Zeile, nennt die Meldung diese Zeile.

RETURN WITHOUT GOSUB

?RETURN WITHOUT GOSUB ERROR

RETURN kommt an, obwohl kein GOSUB dorthin gesprungen ist.

10 RETURNkein GOSUB vorher

Rufen Sie das Unterprogramm mit GOSUB auf. RETURN steht an dessen Ende, nicht am Anfang des Programms.

OUT OF DATA

?OUT OF DATA ERROR

READ will einen weiteren Wert, aber die DATA-Liste ist zu Ende. Die Meldung zeigt die Zeile mit dem READ.

10 READ A,B
20 DATA 1ein Wert zu wenig

Ergänzen Sie die Liste, hier 20 DATA 1,2. Soll dieselbe Liste noch einmal gelesen werden, setzen Sie vorher RESTORE.

ILLEGAL QUANTITY

?ILLEGAL QUANTITY ERROR

Eine Zahl liegt außerhalb des erlaubten Bereichs. SQR und LOG wollen keine negative Zahl. CHR$ nimmt 0 bis 255. Bei POKE geht die Adresse von 0 bis 65535 und der Wert von 0 bis 255. Ein Dateiname darf 1 bis 16 Zeichen haben.

PRINT SQR(-1)Wurzel aus einer negativen Zahl

Geben Sie einen Wert im erlaubten Bereich. Vor der Wurzel prüfen Sie zum Beispiel IF X>=0 THEN PRINT SQR(X).

OVERFLOW

?OVERFLOW ERROR

Das Ergebnis ist zu groß. Die größte Zahl ist etwa 1.7E+38.

PRINT 1E38*10liegt darüber

Rechnen Sie mit kleineren Zahlen, oder fangen Sie große Zwischenergebnisse ab, bevor Sie weiter multiplizieren.

OUT OF MEMORY

?OUT OF MEMORY ERROR

Der Speicher reicht nicht. Meist ist ein Feld zu groß, oder Texte belegen zu viel Platz. Nach dem Einschalten sind 31423 Bytes für Programm und Variablen frei.

DIM A(100,100)über 50 000 Bytes

Wählen Sie ein kleineres Feld. Lange Texte können Sie löschen, indem Sie der Variablen "" zuweisen. CLEAR gibt den ganzen Variablenspeicher frei, das Programm bleibt.

UNDEF'D STATEMENT

?UNDEF'D STATEMENT ERROR

GOTO, GOSUB oder RUN zielt auf eine Zeile, die es nicht gibt.

10 GOTO 20Zeile 20 fehlt

Legen Sie die Zeile an, oder ändern Sie die Nummer im Sprung. LIST zeigt, welche Zeilen es wirklich gibt.

BAD SUBSCRIPT

?BAD SUBSCRIPT ERROR

Der Index eines Feldes liegt außerhalb, oder die Anzahl der Indizes stimmt nicht. Der erste Index ist 0. DIM A(2) hat die Plätze 0, 1 und 2. Ohne DIM geht der Index von 0 bis 10.

10 DIM A(2):PRINT A(3)3 gibt es nicht

Bleiben Sie im Bereich, oder machen Sie das Feld mit DIM größer. Ein Feld mit zwei Indizes sprechen Sie auch mit zweien an: B(1,2), nicht B(1).

REDIM'D ARRAY

?REDIM'D ARRAY ERROR

DIM legt ein Feld an, das es in diesem Lauf schon gibt. Auch dieselbe Größe zählt als zweites Mal.

10 DIM A(2)
20 DIM A(3)A gibt es schon

Lassen Sie das zweite DIM weg. RUN und CLEAR vergessen die Felder, danach darf DIM wieder.

DIVISION BY ZERO

?DIVISION BY ZERO ERROR

Geteilt wurde durch 0.

PRINT 1/0

Prüfen Sie den Teiler vorher: IF N<>0 THEN PRINT 1/N.

ILLEGAL DIRECT

?ILLEGAL DIRECT ERROR

INPUT und DEF FN gehen nur in einem Programm, nicht im Direktmodus.

INPUT Aohne Zeilennummer getippt

Schreiben Sie 10 INPUT A und starten Sie mit RUN.

TYPE MISMATCH

?TYPE MISMATCH ERROR

Zahl und Text sind vermischt. A ist eine Zahl, A$ ein Text. Beides dürfen Sie nicht einander zuweisen oder miteinander verrechnen.

A="HALLO"Text in eine Zahlvariable

Der Text gehört in A$="HALLO". Eine Zahl aus einem Text holt VAL, einen Text aus einer Zahl STR$.

STRING TOO LONG

?STRING TOO LONG ERROR

Ein Text wird länger als 255 Zeichen. Auch ein Dateiname über 16 Zeichen fällt nicht darunter, der ergibt ILLEGAL QUANTITY.

10 A$=""
20 FOR I=1 TO 256
30 A$=A$+"X"
40 NEXT I

In Zeile 30 kippt es bei 256 Zeichen. Lassen Sie die Schleife nur bis 255 laufen, oder schreiben Sie den Text in mehrere Variablen.

FORMULA TOO COMPLEX

?FORMULA TOO COMPLEX ERROR

Ein Textausdruck braucht mehr als drei Zwischenergebnisse auf einmal. So viele hebt BASIC nicht auf.

Teilen Sie den Ausdruck. Erst zwei Teile in eine Variable, dann den Rest:

A$=LEFT$("AB",1)+MID$("CD",2,1)
PRINT A$+RIGHT$("EF",1)

CAN'T CONTINUE

?CAN'T CONTINUE ERROR

CONT kann nicht weitermachen. Entweder steht das Programm nicht an einem STOP, an Pause oder an Strg+C, oder Sie haben es in der Pause geändert.

CONTdirekt nach dem Einschalten

Halten Sie mit STOP an und tippen Sie CONT, ohne vorher eine Zeile zu ändern. Nach einer Änderung hilft nur RUN.

UNDEF'D FUNCTION

?UNDEF'D FUNCTION ERROR

FN ruft eine Funktion, die DEF FN in diesem Lauf nicht angelegt hat.

PRINT FNA(1)kein DEF FNA

Definieren Sie sie vorher im Programm, zum Beispiel 10 DEF FNA(X)=X*X, und rufen Sie sie erst danach auf.

REDO FROM START

?REDO FROM START

INPUT wollte eine Zahl und hat einen Text bekommen. Das Programm bricht nicht ab. Sie geben die ganze Zeile noch einmal ein.

10 INPUT A

Tippen Sie auf das Fragezeichen zum Beispiel HALLO, kommt die Meldung, und INPUT fragt erneut. Tippen Sie eine Zahl.

EXTRA IGNORED

?EXTRA IGNORED

INPUT hat mehr Werte bekommen, als Variablen da sind. Die überzähligen fallen weg, das Programm läuft weiter.

10 INPUT A

Tippen Sie 1,2, bleibt A gleich 1 und die 2 verschwindet. Brauchen Sie beide, schreiben Sie INPUT A,B.

Diskette

Diese Meldungen kommen von LOAD, SAVE, DIR und DELETE. Wie die Diskette angeschlossen wird, steht in Kapitel 6.

NO DISK

?NO DISK ERROR

Am seriellen Anschluss ist kein Laufwerk verbunden.

LOAD "test"ohne angeschlossene Diskette

Schließen Sie sie an, wie es Kapitel 6 beschreibt, und geben Sie den Befehl noch einmal.

FILE NOT FOUND

FILE NOT FOUND

Die Datei gibt es auf der Diskette nicht. Das Programm im Speicher bleibt, wie es ist. Groß- und Kleinschreibung zählen.

LOAD "fehlt"kein fehlt.prg und kein fehlt.bas

DIR zeigt die vorhandenen Namen. Laden Sie einen davon, oder speichern Sie die Datei erst mit SAVE.

BAD LOAD

BAD LOAD

Eine .prg-Datei passt nicht in den Speicher. Die ersten beiden Bytes müssen die Ladeadresse $0441 sein, also 65 und 4, und die Datei darf nicht zu groß sein. Der Speicher bleibt leer.

Nehmen Sie eine Datei, die so aufgebaut ist wie in Kapitel 7. Ein BASIC-Programm laden Sie als .bas, nicht als .prg.

NO PROGRAM

NO PROGRAM

SAVE findet kein Programm im Speicher.

NEW
SAVE "leer"nichts zum Speichern

Schreiben Sie erst ein Programm, dann SAVE.

EMPTY FILE

EMPTY FILE

Die Datei ist da, enthält aber kein Programm.

LOAD "leer"die Datei hat keine Zeilen

Speichern Sie das Programm neu, oder laden Sie eine andere Datei. DIR zeigt die Größe. 0 Bytes ist leer.
