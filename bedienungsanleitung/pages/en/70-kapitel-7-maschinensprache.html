BASIC is comfortable, but too slow for some things. Then you address the processor directly. A machine-language program is a sequence of bytes in memory. The 6502 executes them one after the other. This chapter presents the processor, a few instructions, and the ways to load such a program and start it from BASIC.

The 6502 Processor

The 6502 works with one byte, a number from 0 to 255. It knows 65536 memory locations, from 0 to 65535. In machine code, addresses are written in hexadecimal, with a dollar sign in front: $0000 to $FFFF. BASIC wants the same addresses in decimal.

RegisterWidthJob
A8 bitthe accumulator. This is where the result of a calculation lands
X and Y8 bitcounting and forming addresses
PC16 bitaddress of the next instruction
S8 bitpoints to the stack
P8 bitflags, for example whether the last result was zero

Two areas have fixed jobs. The stack lies at $0100 to $01FF. The processor puts the return address there when it calls a subroutine. The zero page, $0000 to $00FF, it reaches with shorter instructions. BASIC uses that itself.

AreaAddressContents
Program$0440–$7EFFBASIC and your machine-language programs
Input and output$7F00–$7FFFdisplay, keyboard, serial interface, SID
ROM$8000–$FFFFBASIC, Kernal and monitor

A Few Instructions

An instruction begins with one byte, the opcode. One or two bytes often follow: a value or an address. The character # means: take this number itself, not the contents of a memory location.

InstructionExampleEffect
LDALDA #65loads 65 into the accumulator, the letter A
STASTA $7E00writes the accumulator to the address
LDXLDX #0loads register X
JSRJSR $FF80calls the subroutine at the address
RTSRTSreturns from the subroutine

JMP $7E00 jumps as well, but remembers no return address. An address is stored with the low byte first. $FF80 becomes the bytes 128 and 255.

Loading Machine-Language Programs

A finished machine-language program usually comes in a file with the extension .prg, as on the Commodore 64. The first two bytes are the load address, the low one first. It must be $0441, that is the bytes 65 and 4. Behind them stands a BASIC line containing only SYS and the start address, and behind that the machine code.

LOAD "name" stores the image and puts the end of the variables behind it, so that RUN does not overwrite the code. LIST shows the SYS line, RUN executes it. If the address does not fit or the file is too large, the memory stays empty and BAD LOAD appears. SAVE writes only the BASIC lines, not the machine code.

The game raid is such a file. Once the drive from Chapter 6 is connected, LOAD "raid" and RUN start it. Up and down dodge the walls, Q returns to BASIC.

You can also put the same bytes there by hand: in the monitor from Chapter 6, where G starts it, or from BASIC with POKE, as at the end of this chapter.

SYS, PEEK and POKE

POKE address, value writes one byte. PEEK(address) reads one. SYS address jumps there. If the machine-language program ends with RTS, BASIC continues afterwards.

POKE 32256,96
PRINT PEEK(32256)
SYS 32256

32256 is $7E00, high up in memory. 96 is the instruction RTS. PRINT shows 96 as a check, SYS returns immediately. Address and value must be in range: the address from 0 to 65535, the value from 0 to 255. Otherwise ?ILLEGAL QUANTITY ERROR appears.

Caution

POKE writes anywhere, including right into your BASIC program. That begins at 1089 ($0441). Zero page and stack belong to the system. The ROM from 32768 ($8000) cannot be changed.

The Kernal Jump Table

From $FF80 on, fixed entry points lie ready for display, keyboard and sound. A machine-language program calls them with JSR. The addresses stay the same, even if the firmware behind them changes. A, X and Y are modified in the process. Only when reading a key are X and Y preserved.

AddressCallEffect
$FF80JSRclear the display
$FF83JSRset the cursor. A is the row 0 to 3, X the column 0 to 39
$FF86JSRoutput the character in A
$FF89JSRunderscore: A = 0 off, otherwise on
$FF8CJSRkey into A, or 0 if none is pressed
$FF8FJSRwait A milliseconds
$FF92JSRsilence the SID
$FF95JSRsound effect, A = 1 to 9 as with EFFECT

The arrow keys come through as 17 left, 18 right, 19 up and 20 down.

A Machine-Language Program from DATA

Instead of a .prg file, BASIC can put the bytes in place itself. READ fetches them from DATA, POKE writes them, SYS starts. This program clears the display and writes an A in the upper left corner:

BytesInstructionEffect
32, 128, 255JSR $FF80clear the display
169, 65LDA #65the letter A into the accumulator
32, 134, 255JSR $FF86output the character
96RTSback to BASIC
 
10 AD=32256
20 FOR I=0 TO 8
30 READ B
40 POKE AD+I,B
50 NEXT I
60 SYS AD
70 DATA 32,128,255,169,65,32,134,255,96

The nine bytes in line 70 stand in the same order as in the table. $FF80 becomes 128, 255 and $FF86 becomes 134, 255. Line 60 jumps to 32256. Afterwards BASIC waits for input again.

Note

32256 ($7E00) lies high up, away from the BASIC program. BASIC stores string variables from the top of memory downward. Many or long strings can overwrite these bytes.
