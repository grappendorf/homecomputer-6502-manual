Via the micro-USB port on the back you connect the HomeComputer 6502 to a PC. This opens up three new possibilities: you can use the monitor to look into memory, you can save and load programs on a disk on the PC, and you can run BASIC on the PC, with a large screen and the PC keyboard.

The Connection to the PC

Plug a USB cable into micro-USB port 5 on the back (Chapter 1) and the other end into the PC. Inside the computer is a USB-to-serial converter. The PC sees it as a serial port. Under Linux it is usually called /dev/ttyUSB0.

The port works at 19200 baud, 8 data bits, no parity, one stop bit. In short: 19200 8N1. But you do not have to worry about the settings. Three scripts from the tools folder of the firmware project take care of that, one for each mode:

ModeScriptFor
Monitortools/terminal/serial-pico.shlooking into memory and changing it
Disktools/disk/serial-disk.shDIR, LOAD, SAVE and DELETE on the device
BASIC on the PCtools/terminal/serial-basic.shBASIC in the PC's terminal, disk included

The scripts run under Linux. They need the terminal program picocom and the Ruby programming language. If your port is not /dev/ttyUSB0, pass its name as the last argument, for example tools/terminal/serial-pico.sh /dev/ttyUSB1.

Note

Only one program can use the port at a time. Quit one script before starting the next.

The Monitor

The monitor is a small program in the firmware that constantly listens on the serial port in the background. With it you can view the computer's memory byte by byte, change it and start machine-language programs. It works independently of BASIC: while you are in the monitor on the PC, you can keep using BASIC on the device as normal.

Start it on the PC:

tools/terminal/serial-pico.sh

You can also connect directly with picocom:

picocom -b 19200 --imap lfcrlf --omap crlf /dev/ttyUSB0

The script additionally configures the port correctly beforehand. If your keystrokes only arrive after Return with the direct call, use the script. The monitor greets you with a star * as its prompt. Type ? and Return, and a short help text appears:

*?
A[.B] dump  A:hh poke  AG jsr
*

The Commands

You write all addresses and values in hexadecimal, i.e. with the digits 0 to 9 and A to F, upper or lower case. A leading $ is not required.

InputEffect
8000show 16 bytes from address 8000, as hex numbers and as characters
8000.80FFshow all bytes from 8000 to 80FF
Return aloneshow the next 16 bytes
1000: 12 34 ABwrite the bytes 12, 34 and AB starting at address 1000
1000Gstart the machine-language program at address 1000
?show help
Ctrl + Cabort a long output or the input line

This is what it looks like:

*8000
8000 78 D8 A2 FF 9A A9 00 AA 95 00 E8 D0 FB 20 72 80  x............ r.
*1000: 12 34 ab
*1000.1003
1000 12 34 AB 00  .4..
*xyz
?
*

Every line starts with the address. Then come the bytes, on the right the same bytes as characters. Non-printable characters appear as a period. If the monitor does not understand an input, it answers with ?. An input line may be at most 31 characters long. Quit picocom with Ctrl + A and then Ctrl + X.

Caution

The monitor writes anywhere, including right into your BASIC program. The program and variables live from 0440 to 7EFF. From 7F00 on are the input and output chips, from 8000 the ROM, which cannot be changed. The memory map is in Appendix C.

A machine-language program you start with G must end with the RTS instruction. The monitor then returns and shows the star again. How to write machine-language programs is shown in Chapter 7.

The Disk

The HomeComputer 6502 has no drive of its own. Instead, a folder on the PC serves as the disk. Start on the PC:

tools/disk/serial-disk.sh

By default the examples folder of the firmware project is the disk. It is the best way to get to know the commands, because the example programs from this manual are already there. For your own programs, pass a different folder, e.g. tools/disk/serial-disk.sh ~/my-programs. The script reports:

Disk ready: …/homecomputer-6502-firmware/examples
Device: /dev/ttyUSB0

While it is running, BASIC on the device understands four new commands:

CommandEffect
DIRshows what is on the disk
LOAD "name"loads a program and replaces the one in memory
SAVE "name"saves the program from memory
DELETE "name"deletes a program from the disk

What Is on the Disk

DIR shows every file in the folder with its size in bytes and its name, sorted alphabetically, including files that are not programs. After three files the display waits with MORE - PRESS A KEY for a key, and the LED lights up. At the end it says END OF DIRECTORY. Press Pause to abort.

Loading and Saving

While loading and saving, a bar shows the progress. Afterwards the display says LOADED or SAVED. A few rules:

  • A name is at most 16 characters long and is enclosed in quotation marks.
  • Without an extension, the computer first looks for a file with .prg, then with .bas. .bas files are BASIC programs, .prg files machine-language programs (Chapter 7).
  • SAVE writes the program as an ordinary text file with the extension .bas, exactly as LIST shows it. You can view and edit it on the PC with any text editor.
  • If the file does not exist, the computer reports FILE NOT FOUND. The program in memory is then kept.
  • If there is no program in memory, SAVE just reports NO PROGRAM and writes nothing.

Deleting

delete "test"
DELETE? (Y/N) y
DELETED

DELETE asks first. Only Y deletes the file; any other key leaves it alone.

Ejecting the Disk

Press Ctrl + C in the script's window on the PC. The script reports Ejected and exits, and the monitor is ready again. If you then try DIR, LOAD or SAVE, the computer reports ?NO DISK ERROR.

BASIC on the PC

Longer programs are easier to write on the PC: big screen, familiar keyboard, copy and paste. To do so, bring BASIC into the PC's terminal:

tools/terminal/serial-basic.sh

The script starts picocom and switches BASIC over to the serial port. BASIC's welcome message appears in the terminal, and you work there just like on the device. The computer's keyboard and display stay silent in the meantime.

6502 HOMECOMPUTER BASIC V1.1
COPYRIGHT 1978 MICROSOFT
31423 BYTES FREE
print 2+3
 5

The disk comes along too: DIR, LOAD, SAVE and DELETE work in the terminal as usual, again with the examples folder. You pass a different folder just like with the disk: tools/terminal/serial-basic.sh ~/my-programs. A few differences from the device:

  • LIST and DIR scroll through without MORE. The terminal can scroll back, after all.
  • The terminal has 80 columns and 24 rows. CLS and LOCATE refer to that size. With TERM 100,30 you set a different size; TERM alone shows the current one. The terminal window must be at least that large.
  • CURSOR BLINK and DISPLAY have no effect in the terminal.

Device and PC Together

Even while BASIC runs in the terminal, a program can reach the device's display and keyboard. Append #1 to PRINT or INPUT for that. #2 means the serial port, i.e. the terminal:

10 PRINT #1,"YOUR NAME";
20 INPUT #1,N$
30 PRINT #1,"THANKS"
40 PRINT "TYPED ON THE DEVICE: ";N$

The program asks its question on the device's display, reads the answer from its keyboard and writes the result to the terminal. This way you can build, for example, a quiz where the quizmaster sits at the PC.

Back to the Device

Type QUIT. BASIC returns to the display and keyboard, and the terminal shows the monitor again. The same happens if you quit picocom with Ctrl + A, Ctrl + X. Your program stays in memory.

In the Emulator

For the emulator there are the same scripts with mame instead of serial in the name: mame-pico.sh, mame-disk.sh and mame-basic.sh. They find the emulator's port on their own.
