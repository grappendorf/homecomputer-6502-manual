With variables, loops, IF and INPUT, you can already do a lot. This chapter adds the tools that keep larger programs manageable: arrays for many values, subroutines, data stored inside the program, your own functions, and randomness. After that, you will learn how to control the display precisely, read the keyboard directly, and switch the LED. At the end there is a game that brings it all together.

Arrays with DIM

Suppose you want to store five scores. You could use five variables: P1, P2 and so on. An array is easier. It is a single variable with several slots, addressed by a number called the index:

10 DIM P(4)
20 S=0
30 FOR I=0 TO 4
40 INPUT "POINTS";P(I)
50 S=S+P(I)
60 NEXT I
70 PRINT "AVERAGE:";S/5
80 FOR I=0 TO 4
90 IF P(I)>S/5 THEN PRINT "VALUE";I+1;"IS ABOVE"
100 NEXT I

DIM P(4) creates an array with the slots P(0) through P(4) – five in total. The index may be a variable or an expression. That is exactly what makes arrays so useful: a loop can work through all the slots one after another.

  • An array used without DIM has slots 0 through 10.
  • An index outside the array causes ?BAD SUBSCRIPT ERROR.
  • Each array may be created with DIM only once. A second time gives ?REDIM'D ARRAY ERROR. RUN and CLEAR delete all arrays.
  • Arrays exist for all three kinds of variables: DIM N$(20) for text, DIM Z%(100) for integers.
  • An array can also have two indices, like a table with rows and columns: DIM F(2,3), then F(2,3)=7.

Subroutines

Often a program needs the same statements in several places. Instead of writing them out repeatedly, you put them in a subroutine. GOSUB jumps into it, RETURN jumps back to just after the GOSUB:

10 PRINT "START"
20 GOSUB 100
30 PRINT "MIDDLE"
40 GOSUB 100
50 END
100 PRINT "--------"
110 RETURN

The END in line 50 is important. Without that line, the program would run straight into the subroutine after the second call. At the RETURN it would not know where to go back to, and would report ?RETURN WITHOUT GOSUB ERROR. That is why subroutines go at the end, with an END in front of them.

A subroutine may itself use GOSUB. Each RETURN goes back to the most recent GOSUB.

Dispatching with ON

ON uses a number to choose one of several jump targets:

ON W GOSUB 100,200,300

If W equals 1, it goes to line 100. At 2 to line 200, at 3 to line 300. If W is 0 or greater than the number of targets, nothing happens and the program continues with the next statement. Fractional numbers are rounded down. ON W GOTO … works the same way, just without coming back.

DATA and READ

Some values are already known when you write the program: a word list, the names of the days of the week, the notes of a melody. You write such values after DATA. READ reads them, in order, into variables:

10 DIM T$(6)
20 FOR I=0 TO 6:READ T$(I):NEXT I
30 INPUT "DAY (1-7)";N
40 IF N<1 OR N>7 THEN 30
50 PRINT "THAT IS ";T$(N-1)
60 DATA MONDAY,TUESDAY,WEDNESDAY,THURSDAY
70 DATA FRIDAY,SATURDAY,SUNDAY

It does not matter where the DATA lines are. The computer reads them in line-number order, across all DATA lines. A few rules:

  • Values are separated by commas. If a text contains a comma itself, put it in quotation marks: DATA "CHERRY, SWEET",3.
  • Text after DATA stays exactly as you type it, lowercase or uppercase. If the program will later compare it against uppercase letters, type it with Shift.
  • RESTORE moves the read pointer back to the start. The next READ reads the first value again.
  • When all values have been read, another READ causes ?OUT OF DATA ERROR.

If you do not know in advance how many values there are, put an end marker at the end of the list – *, for example – and read until it arrives. The game at the end of this chapter does it that way.

Functions

A function takes a value in parentheses and returns a result. You can use it anywhere a number is allowed: PRINT SQR(16), A=INT(X). The most important arithmetic functions:

FunctionResultExample
INT(x)largest whole number not greater than xINT(3.7) = 3, INT(-3.7) = −4
ABS(x)absolute value, without signABS(-4) = 4
SGN(x)sign: −1, 0 or 1SGN(-2) = −1
SQR(x)square rootSQR(16) = 4
SIN, COS, TAN, ATNtrigonometric functions, angles in radiansATN(1)*4 = 3.14159266
EXP(x), LOG(x)e to the power of x, natural logarithm

You write powers with ^: 2^10 is 1024. There is no separate function for the remainder of a division. You get it with A-INT(A/B)*B. For 17 divided by 5 that is 2.

Your own functions with DEF FN

A calculation you need often can be defined as your own function. The name begins with FN, followed by a variable name:

10 DEF FNQ(A)=A*A
20 PRINT FNQ(7)

This prints 49. The A in the parentheses is just a placeholder. When the function is called, the value you pass takes its place. A function takes exactly one such value. DEF FN works only in a program; typed in directly, the computer reports ?ILLEGAL DIRECT ERROR.

Random numbers

RND(1) returns a random number that is at least 0 and less than 1. For a die, though, you need the whole numbers from 1 to 6. The formula for that is:

INT(RND(1)*6)+1

RND(1)*6 gives a number from 0 up to just under 6. INT cuts off the fractional part, leaving 0 through 5. Adding one gives 1 through 6. In general, INT(RND(1)*N)+1 gives a number from 1 to N. As your own function:

10 DEF FNW(X)=INT(RND(1)*X)+1
20 FOR I=1 TO 10:PRINT FNW(6);:NEXT I

The seed value

The numbers from RND are not truly random. They are calculated from a seed value. After power-on it is always the same, which is why the same numbers always come up. You set a new seed with a negative number in the parentheses: X=RND(-42). The same seed produces the same sequence. That is handy for testing.

For real randomness you need a seed that nobody can predict. A tried-and-true trick: the program counts until you press a key. How long that takes is different every time:

10 PRINT "PRESS ANY KEY."
20 S=0
30 S=S+1:IF KEY(0)=0 THEN 30
40 X=RND(-S)

How KEY works is described later in this chapter. RND(0), by the way, returns the last random number once again.

Strings

You can work with text, too. These functions take strings apart, examine them, and convert them:

FunctionResultExample
LEN(a$)number of charactersLEN("HELLO") = 5
LEFT$(a$,n)the first n charactersLEFT$("HELLO",2) = HE
RIGHT$(a$,n)the last n charactersRIGHT$("HELLO",3) = LLO
MID$(a$,p,n)n characters starting at position pMID$("HELLO",2,3) = ELL
MID$(a$,p)everything from position p onMID$("HELLO",4) = LO
ASC(a$)character code of the first characterASC("A") = 65
CHR$(n)the character with code nCHR$(66) = B
STR$(x)number as textSTR$(42) = " 42"
VAL(a$)text as numberVAL("12.5") = 12.5

Positions in a text count from 1. STR$ puts a space in front of positive numbers, just like PRINT. VAL reads the number at the beginning of the text. If there is none, the result is 0. Every letter has a character code: A through Z are 65 through 90, a through z are 97 through 122. You can find the character set in Appendix D.

This program writes a word backwards. The loop runs from the end to the beginning and picks out one character at a time with MID$:

10 INPUT "WORD";W$
20 FOR I=LEN(W$) TO 1 STEP -1
30 PRINT MID$(W$,I,1);
40 NEXT I
50 PRINT

Controlling the display

So far, PRINT has simply written line after line and the display has scrolled upward. For games and tidy output, however, you want to decide for yourself where things appear. These commands do that:

CommandEffect
CLSclear the display, cursor to top left
LOCATE z,sput the cursor at row z (0 to 3) and column s (0 to 39)
CURSOR OFF / CURSOR ONturn the underline cursor off and on
CURSOR BLINK ON / OFFmake the character under the cursor blink
DISPLAY OFF / DISPLAY ONdarken the display and bring it back. The text is preserved.
SLEEP swait s seconds, fractions included: SLEEP 0.1

This program counts the seconds, always in the same place:

10 CLS:CURSOR OFF
20 T=0
30 LOCATE 1,14:PRINT "SECONDS:";T;
40 SLEEP 1:T=T+1:GOTO 30

Note the semicolon at the end of line 30. Without it, PRINT moves the cursor to the next line. In the bottom line, the whole display then scrolls up. When you work with LOCATE, always end PRINT with ;.

If you stop the program with Pause, the cursor stays off. Type CURSOR ON and it is back.

Tip

Inside PRINT there are also TAB(n) and SPC(n). TAB(10) advances to column 10, SPC(3) prints three spaces. POS(0) tells you which column the cursor is currently in.

Reading the keyboard

INPUT waits until you press Return. For a game that is too slow. The function KEY(0) instead checks which key is pressed at this very moment, without waiting. If none is pressed, it returns 0; otherwise the character code of the key. The number in the parentheses does not matter.

This program shows the codes of the keys you press:

10 CLS:CURSOR OFF
15 IF KEY(0)<>0 THEN 15
20 K=KEY(0):IF K=0 THEN 20
30 PRINT K;
40 IF KEY(0)<>0 THEN 40
50 GOTO 20

Line 20 waits until a key is pressed. Line 40 waits until it is released again. Without line 40, the program would keep printing the code for as long as you hold the key. Line 15 waits at the start until you have released Return after RUN. Otherwise the first number would always be 13.

KeyCodeKeyCode

Esc27End22
Backspace8Del23

Because KEY reports for as long as a key is held down, it works well for movement. Here an asterisk wanders across the display with the arrow keys. Hold the key down and it keeps moving. Esc ends the program:

10 CLS:CURSOR OFF:X=20:Y=1
20 LOCATE Y,X:PRINT "*";
30 K=KEY(0):IF K=0 THEN 30
40 LOCATE Y,X:PRINT " ";
50 IF K=17 AND X>0 THEN X=X-1
60 IF K=18 AND X<39 THEN X=X+1
70 IF K=19 AND Y>0 THEN Y=Y-1
80 IF K=20 AND Y<3 THEN Y=Y+1
90 IF K=27 THEN CLS:CURSOR ON:END
100 SLEEP 0.1:GOTO 20

Line 40 erases the asterisk at its old position before lines 50 through 80 compute the new one. The conditions after AND keep it inside the display. The SLEEP in line 100 slows it down. Without that line, even a brief key press would send it several places at once.

The LED

There is an LED at the top right of the unit. After power-on and after a reset it lights up by itself for one second. After that it belongs to you: LED ON turns it on, LED OFF turns it off.

10 LED ON
20 SLEEP 0.5
30 LED OFF
40 SLEEP 0.5
50 GOTO 10

The program makes the LED flash once per second until you stop it. You can use the LED as a signal – when a game is won, for example, or to show that a long program is still working.

Note

ON and OFF are BASIC words. A variable therefore may not be named OFF.

A game: Hangman

To finish, here is a larger program that uses almost everything from this chapter and the last one. The computer picks a word. You guess letter by letter. Every letter that is not in the word counts as a miss. After eight misses, you have lost.

The program is long. Take your time typing it in and check each section with LIST. You can also find it in the firmware project as examples/galgen.bas. If the disk drive from Chapter 6 is connected, load it with LOAD "galgen". The sections in detail:

Preparation

10 REM HANGMAN
20 DIM WL$(20),G(25)
30 DEF FNR(X)=INT(RND(1)*X)
40 N=0
50 READ A$:IF A$="*" THEN 80
60 N=N+1:WL$(N)=A$
70 GOTO 50
80 CLS:CURSOR OFF
90 PRINT "HANGMAN":PRINT
100 PRINT "PRESS ANY KEY."
105 IF KEY(0)<>0 THEN 105
110 S=0
120 S=S+1:IF KEY(0)=0 THEN 120
130 X=RND(-S)
140 IF KEY(0)<>0 THEN 140

Line 20 creates two arrays. WL$ is the word list. G has one slot for every letter from A to Z. Later, a 1 sits there when the letter has already been guessed. Line 30 defines a function for random numbers from 0 to X−1. Lines 50 through 70 read the words from the DATA lines until the end marker * arrives. N counts them as it goes. Lines 105 through 140 generate the seed for the random numbers using the key-press trick from above.

One round

200 REM NEW ROUND
210 W$=WL$(FNR(N)+1):L=LEN(W$)
220 FOR I=0 TO 25:G(I)=0:NEXT I
230 F=0:R$="":CLS
240 GOSUB 500
250 IF M=0 THEN E=1:GOTO 400
260 IF F=8 THEN E=2:GOTO 400
270 LOCATE 3,0:PRINT "LETTER?        ";
280 GOSUB 600
290 B=ASC(B$)-65
300 IF G(B)=1 THEN 280
310 G(B)=1:T=0
320 FOR I=1 TO L
330 IF MID$(W$,I,1)=B$ THEN T=1
340 NEXT I
350 IF T=0 THEN F=F+1:R$=R$+B$
360 GOTO 240

Line 210 picks a random word W$ of length L. Line 220 forgets all guessed letters; line 230 resets the miss count F and the list of wrong letters R$. Then the loop from line 240 to 360 begins: refresh the display, check whether the round is over, fetch a letter.

Line 290 turns the letter into a number from 0 (A) to 25 (Z), matching the array G. If the letter has already been guessed, line 300 simply fetches the next one. Lines 320 through 340 check every position of the word. T becomes 1 as soon as the letter occurs anywhere.

Watch out

The NEXT I deliberately sits on its own line. If it were in line 330 after the IF, it would only run when the condition is true. With any other letter, the loop would hang.

End of the round

400 ON E GOSUB 700,800
410 LOCATE 3,0:PRINT "ANOTHER (Y/N)?";
420 GOSUB 600
430 IF B$="Y" THEN 200
440 IF B$<>"N" THEN 420
450 CLS:CURSOR ON:END

E is 1 when all letters have been found, and 2 after eight misses. ON E GOSUB jumps to the matching subroutine. After that, the program asks for a new round. Any key other than Y and N is ignored.

The subroutines

500 REM DISPLAY
510 LOCATE 0,0:PRINT "HANGMAN";
520 LOCATE 0,27:PRINT "MISSES";F;"/ 8";
530 LOCATE 1,0:M=0
540 FOR I=1 TO L:C$=MID$(W$,I,1)
550 IF G(ASC(C$)-65)=1 THEN PRINT C$;" ";:GOTO 570
560 PRINT "_ ";:M=M+1
570 NEXT I
580 LOCATE 2,0:PRINT "WRONG: ";R$;
590 RETURN

The subroutine starting at line 500 draws the display. For every position of the word it prints the letter if it has already been guessed, otherwise a dash. M counts the dashes. If M is 0 at the end, the word is complete.

600 REM GET KEY
610 K=KEY(0):IF K=0 THEN 610
620 IF KEY(0)<>0 THEN 620
630 IF K>=97 AND K<=122 THEN K=K-32
640 IF K<65 OR K>90 THEN 610
650 B$=CHR$(K):RETURN

The subroutine starting at line 600 waits for a key and for its release. Line 630 turns lowercase letters into uppercase, since their codes are exactly 32 apart. Line 640 lets only letters through. That way the game works with and without Shift.

700 REM WON
710 LOCATE 3,0:PRINT "CORRECT!          ";
720 FOR I=1 TO 5:LED ON:SLEEP 0.2:LED OFF:SLEEP 0.2:NEXT I
730 RETURN
800 REM LOST
810 FOR I=0 TO 25:G(I)=1:NEXT I
820 GOSUB 500
830 LOCATE 3,0:PRINT "YOU LOST.         ";
840 SLEEP 2
850 RETURN

On a win, the LED flashes five times. On a loss, line 810 simply marks all letters as guessed. The display subroutine then shows the whole word, without any extra code. The spaces after the messages overwrite leftovers from the previous line.

The word list

900 DATA COMPUTER,PROCESSOR,KEYBOARD,MEMORY
910 DATA PROGRAM,LOOP,VARIABLE,DISPLAY
920 DATA DISK,MONITOR,CHARACTER,SOUND
930 DATA *

Add your own words simply as further DATA lines before line 930. Three rules apply: uppercase letters A to Z only, no umlauts, at most 20 letters – otherwise the word does not fit on a line. In total, 20 words fit in the array. For more, enlarge WL$ in line 20.

What is in this program: arrays (DIM), subroutines (GOSUB, ON … GOSUB), data (DATA, READ), a user-defined function (DEF FN), random numbers with a seed (RND), string functions (LEN, MID$, ASC, CHR$), the display (CLS, LOCATE, CURSOR), the keyboard (KEY), and the LED. Plus loops, conditions, and variables from Chapter 3. Once you understand this program, you can write games of your own.
